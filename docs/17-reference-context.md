# 登録資料・Skillsによる追加コンテキスト（案CのMVP）

手入力の追加コンテキストを残し、規約・ADR・技術資料・Agent Skillsを用途別に選んで利用する。検索とファイル読み込みはExtension Hostで完結し、検索用の外部APIやバックエンドは使わない。

## 使い方

1. 相談入力欄の「追加コンテキスト」を開く。
2. 「参照先・Skills」で用途と保存範囲を選び、「ファイル追加」または「フォルダー追加」を押す。
3. 規約では対象言語IDとワークスペース相対globを指定する。空欄は全言語・全パス。`src/**/*.{ts,tsx},test/**` のような波括弧とカンマ区切りを併用できる。複数ルートでは適用ルートも選べる。
4. Skillsは「Skillsを選択」で有効にする。選択状態は登録先と同じ範囲に保存され、次回以降の相談にも反映される。
5. 「送信予定」を開き、選択された資料、行範囲、理由、入力予算による省略を確認する。

「読込対象・選択状況を確認」から実際の文書をエディタで開ける。「再確認」は監視から通知が来ない変更にも使用する。「登録解除」は登録とメモリキャッシュを外す操作で、元の資料を削除しない。

保存範囲の「共通」は他のワークスペースでも使える登録先を意味する。機密性の判定や現在の相談への適合性を保証するものではない。

## 選択規則

| 用途 | 選択方法 |
| --- | --- |
| 規約 | 設定した言語・パス・ルートに一致する資料を優先する |
| ADR | 質問・課題文・コード文脈の関連語で選ぶ。廃止・置換・却下済みは通常検索から外す |
| 技術・設計資料 | ファイル名・タイトル・本文の関連語で選ぶ |
| Skills | ユーザーが有効にしたSkillを読み込む。未選択Skillは自動適用しない |

「優先資料を選択」で資料を固定候補にできる。未選択の普通の資料も関連検索の対象になる。ADRの旧判断は明示選択、または過去の経緯についての質問で参照できる。

ADRの状態はYAML frontmatterの `status`、または `Status: ...` / `状態: ...` の行から読む。状態不明を有効と断定せず、更新日時だけで決定を置換しない。現時点ではADR間の置換グラフまでは構築しない。

資料本文はMarkdownの見出しと上限を基準に分割し、コードフェンスをなるべく保つ。質問・手入力課題を主に、言語・選択コード・診断を補助に検索する。日本語は正規化と文字bigramも使う。検索該当なしでは無関係な資料を追加しない。

通常は最大5断片を候補にし、Skillの明示リンク先を含めて最大8件とする。規約の全件適用を保証するものではない。プロンプト用の予算は直列化の付帯情報を含めて次のとおり。

| 対象 | 予算 |
| --- | --- |
| 規約・ADR・資料の断片（Skillの関連資料を含む） | 残り文字数の30%以内、最大6,000文字 |
| Skill本文 | 残り文字数の40%以内、最大20,000文字 |
| 登録資料全体 | 残り文字数の50%以内（上の2つの合計の上限） |

Skillは分割すると意味が変わるため独立した枠で丸ごと扱う。予算に全文が収まらない断片・Skillは丸ごと省略し、送信予定に理由を表示する。手入力課題の既存4,000文字正規化は変更しない。

明示選択は関連語の一致数より優先し、長い1文書で枠を埋めないように文書ごとの代表箇所を先に選ぶ。Skillの関連資料も、先頭固定ではなく質問・コード文脈に関連する箇所を選ぶ。Ollamaの送信予定には、実送信と同じ説明の深さ・入力予算を使う。

## Agent Skills対応範囲

[公開形式](https://agentskills.io/specification)の `SKILL.md` を解析する。必須の名前・説明、任意の互換性・文字列メタデータなどを検証し、YAMLの重複キー、未知タグ、エイリアス展開、不正な階層を拒否する。`name` は親ディレクトリ名と一致させる。

`SKILL.md` を直接登録する場合と、Skillを含むディレクトリを登録する場合の両方に対応する。最初はカタログを表示し、選択されたSkillについてのみ、本文のMarkdownリンクで指定された `references/...` のテキストを追加で読む。URL取得、曖昧な自然文参照、再帰的な参照チェーンは未対応。

「利用方法」で参考資料／学習・説明の手順を切り替える。手順モードでもNaviComの学習支援方針・現在の質問・安全制約より優先しない。`allowed-tools` は実行許可にはならず、`scripts/` の起動、ファイル変更、パッケージの自動導入は行わない。`assets/` の解析も対象外。

## 送信とプライバシー

- 登録先は既定でローカル限定。Copilot等で使用するには「利用方法」から外部送信を明示的に許可する。
- 接続先（自動切り替え後の実際の送信先）が確認済みのローカルLLMでない場合、ローカル限定の断片は本文を送らずに除外し、相談自体は続ける。除外した断片は送信予定に「ローカル限定の資料のため、この接続先には送信しません」と表示する。
- ローカル限定は、LM StudioまたはOllamaのloopback接続先かつクラウド名を含まないモデルに制限する。任意のローカルサーバーが外部転送しないことまで検証するものではない。
- ローカルLLMへ送ったローカル限定の断片は、入力予算で省略される可能性があっても保守的にローカル限定として扱う。外部接続先のため除外した断片は会話をローカル限定にしない。
- ローカル限定の参照内容を使った会話にも制約を保存し、後続の外部生成・外部圧縮と共通ナレッジへの保存を停止する。自動助言でこの理由により停止した場合、同じ理由の警告は1回だけ表示し、助言の成功・参照先の変更・手動の相談で表示状態を戻す。
- 外部送信可能な資料から作成するナレッジは、参照元IDをSQLiteにも保存する。再利用時には登録先の現在の許可を確認し、無効・解除・ローカル限定の出所を持つナレッジは再利用しない。ナレッジから作った次の回答にも出所を引き継ぐ。
- 参照先の許可を後から変更しても、すでにローカル限定になった会話を自動的に外部送信可能へ変更しない。外部送信を許可した資料で相談する場合は新しい会話を使用する。
- 参照先を無効化・解除した場合や外部送信許可を取り消した場合は、その出所を持つ過去の回答・派生回答も以後はローカル限定として扱う。
- Workspace Trustがない間は本文を読み込まない。ユーザー設定を含む除外、`.env`、資格情報、依存・生成物等の既存保護パターンを適用する。
- 登録範囲内の実体パスを検査し、シンボリックリンク・ジャンクションは追跡しない。ファイルハンドルから上限付きで読み、読み込み中のサイズ・更新を確認する。
- データ内の指示や区切り文字は、アプリの権限へ昇格させない。資料の全文をsystemロールへ連結しない。

## 保存と更新

登録情報・選択・利用方法は `aiPairNavigator.referenceSources.v1` キーで、ワークスペースの `workspaceState` または共通の `globalState` に保存する。設定をGit管理ファイルへ自動出力しない。

本文はメモリに保持し、参照用SQLiteテーブルを新設しない。通常のプレビューはメモリ内検索を使い、監視通知と「再確認」で読み直す。監視にはVS Codeの `RelativePattern` を使う。

送信前は、送信する断片のファイルだけを走査時と同じ境界検査（リンク・保護パス・範囲外・サイズ）で読み直し、内容ハッシュ・設定世代・送信許可を照合する。不一致なら送信せず、カタログを無効化して次回に再走査する。登録先全体の再走査は、監視通知があった場合と、送信時に前回の走査から30秒以上たっている場合だけ行う（監視除外や外部ツールの保存方法による通知漏れの補完）。カタログの変更判定は文書ID・パス・内容ハッシュで行い、本文全体は比較しない。

資料の登録・設定・選択ダイアログが開いている間はAI要求と排他する。資料収集・再確認中も中断でき、中断後は質問履歴を追加したりAIへ送信したりしない。

会話の `request_plan_json` には出所ID、内容ハッシュ、行範囲、選択理由、送信有無、送信制約を保存する。参照本文は会話DBに複製しない。資料変更後に過去の原文を完全再現する機能はない。

ナレッジには `reference_sources_json` 列を追加する。旧レコードは、現在のワークスペースの元回答から出所を確認できる場合に補完する。元会話がすでに削除されているなど、出所自体が失われたデータを自動的に復元することはできない。

## 上限と今後の拡張

- 新規追加は合計20件まで。ワークスペース切替で共通登録との合計が上限を超えた場合も、既存データは切り捨てず表示・編集できる。UTF-8の `.md`、`.markdown`、`.txt`、`.json` が対象。
- 1ファイル256KiB、参照集合全体で本文20MiB、1,000ファイル、2,000ディレクトリ、10,000走査エントリー、深度12まで。
- 上限・不正形式・読込失敗は登録先に表示する。巨大なディレクトリは対象を絞って登録する。
- ローカルNode Extension Hostから見えるファイルが対象。Remoteと手元PCのファイル・LLM接続先の橋渡し、ブラウザー版、任意の仮想ファイルシステムは未対応。
- FTS5、Embedding、永続索引、Skillのモデル自動選択、完全な日本語意味検索は後続段階。
- 複数のVS Codeウィンドウ間で登録設定を即時同期する仕組みは持たない。

## 検証

`npm test` で既存互換、検索と適用条件、変更・削除・無効化、監視イベント、並行走査、UTF-8・機密・サイズ除外、実際のジャンクション、Skill関連資料、プロンプト予算、出所保存、ルーティング・圧縮・ナレッジの送信境界を検証する。Windowsの実リンク作成は、実行環境にリンク作成権限が必要。

F5で手入力と登録UIを確認する場合は、資料を登録して「送信予定」を開き、Skillの選択、無効化、外部送信許可、次の質問への反映を確認する。Activity Barが見えない場合は、まず `View: Reset View Locations` または開発用 `--user-data-dir` で保存済みUI状態を切り分ける。
