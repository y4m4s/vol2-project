# 追加コンテキストと添付資料

## 基本構成

追加コンテキストは、会話ごとの直接入力とファイル・フォルダー添付で構成する。資料・プロジェクト・Skillsを別の追加枠に分けず、用途・保存先の選択も追加時に求めない。本文の保持・索引化・検索はExtension Host内で行い、資料全体を外部サービスへアップロードしない。

1. 入力欄のファイルアイコンから「コンテキスト」を開く。
2. 補足や課題文を入力するか、「＋追加」からファイル・フォルダーを添付する。
3. 添付の詳細から、利用設定・常に含めるファイル／Skillsの選択・再読み込み・原文の確認を行う。
4. 添付行の×で、その会話から添付を外す。元ファイルは削除しない。

警告の詳細と管理操作は折りたたむ。ローカル限定／外部送信許可済みの状態は添付行に表示する。

## 保存と会話の切り替え

直接入力は会話DBの `additional_context`、添付情報・有効状態・選択・送信許可は `context_sources_json` に保存する。別の会話や新しく作成した会話へ自動適用しない。ホームで添付した下書きは、そのホームから開始する会話へ引き継ぐ。ホームの下書きはセッション内の保持であり、再起動後の復元対象にはしない。

会話に添付した情報は、質問がまだなくても保持する。会話を削除すると、その添付情報も削除する。登録ファイルの実体は元の場所に置き、本文と検索用カタログはメモリに保持する。会話DBへ資料本文を複製しない。

旧 `aiPairNavigator.referenceSources.v1` のワークスペース／共通登録は削除しない。「＋追加 → 以前の登録から」で、選んだ登録だけを現在の会話に取り込める。旧登録を全会話に自動適用しない。

## 本文の扱い

| 対象 | 送信方法 |
| --- | --- |
| 直接入力した補足・課題文 | 現在の前提として全文を含める |
| 通常の添付ファイル・フォルダー | 関連する箇所を検索して含める |
| 「常に全文を含める」にしたファイル | 全文を含める |
| フォルダー内で「常に含める」に選んだファイル | 全文を含める |
| 適用するSkill | 手順本文を全文で含め、付随資料は関連箇所を参照する |

直接入力の既存4,000文字切り詰めは廃止する。入力・保存の上限は10,000文字。必須本文を入力予算に合わせて途中切断しない。モデル入力に収まらない場合の基本的な送信停止は残すが、超過量の提示や範囲変更を補助する専用UIは今回の対象外とする。

ファイルの「利用設定」で全文／検索を切り替える。フォルダーの「常に含めるものを選択」ではファイルとSkillを選ぶ。Skillsの適用数だけに専用の上限は設けず、必須本文の合計にモデル入力予算を適用する。

## 検索とAIへの参照提供

手動相談では、送信許可のある資料のID・相対表示パス・タイトルからカタログを作り、AIに検索語と候補IDを選ばせる。NaviComがその結果に基づいてローカル検索し、取得した本文を最終回答の入力へ渡す。ネイティブのツール呼び出しに依存しないため、既存の各接続先で同じ方式を使う。

- 検索計画は最大1回の追加API呼び出し。検索語は最大3件、候補IDは最大5件。
- カタログは最大8,000文字か、モデル予算から算出した範囲の小さい方。大きい場合は質問との関連性で絞る。
- モデル出力はJSONとして検証し、カタログ外ID・任意のパス・過大な要求を受け付けない。
- 計画が不正／取得できない場合は、質問・直接入力・コード文脈によるローカル検索を使う。中断時は最終回答を要求しない。
- 自動発言はローカル検索のみとし、検索計画の追加API呼び出しを行わない。
- 検索計画の呼び出しも日次利用量へ記録する。検索後に日次上限を再確認し、成功した検索計画の利用量と要求回数は最終回答にも合算する。

無制限の反復走査や、AIが最終回答の途中で何度も追加取得するエージェントループは実装しない。検索の追加段階は、将来この境界内で拡張できる。

本文は見出し・コードフェンスを考慮して分割する。検索による任意の抜粋は通常最大5断片で、Skill関連資料を追加する場合は任意の参照全体の上限を適用する。常に含めるファイルと適用Skillは、この件数で追い出さない。必須でない抜粋はモデルの残り入力予算の50%を上限とする共通枠から選び、種類別の6,000文字／20,000文字枠は使わない。最終的な質問・補足・コード・履歴・添付の合計はモデルプロファイルの入力予算で制御する。

トークン予算は現状の文字数による推定を使用する。プロバイダーごとの厳密な送信前トークン計数や、入出力合算上限からの予約量の再設計は残課題。

## Skills

通常のファイル／フォルダー添付でも `SKILL.md` を認識する。フォルダーは直下に限らず入れ子のディレクトリまで再帰走査する。直接添付したSkillと「常に含める」で選んだSkillは常時適用する。それ以外のSkillも、相対パス・名前・説明を手動相談の検索候補に含め、AIが選んだものをその相談だけに適用する。相談ごとの選択は会話の常時適用設定へ保存しない。自動発言では、従来どおり明示選択したSkillを使う。

YAMLの必須name・description、親ディレクトリ名との一致などを検証し、不正な構造・重複キー・エイリアス等を拒否する。Skill本文の明示的な相対MarkdownリンクをSkill自身のディレクトリから解決する。`references/` や `rules/typescript/` のようなディレクトリへのリンクも配下を再帰走査し、深い階層の関連ファイルを検索・参照する。取得上限内では、ディレクトリ全体の関連性を比較して抜粋を選ぶ。旧Skill専用登録でAIが一時選択した場合は、関連資料を含む再走査を最大1回行う。

`scripts/` は実行せず、関連資料内のscripts・assetsも走査しない。上位ディレクトリへの参照、リンク・ジャンクション、保護対象・ユーザー除外は引き続き除外する。深度上限は明示リンクでも実際の相対パスの深さで判定する。リンク先のURL取得、関連資料本文からの参照チェーンの追跡、ファイル変更、パッケージ導入は行わない。

資料本文やSkillsは信頼しない参照データとして渡す。NaviComの権限、学習支援方針、現在の質問を上書きする指示へ昇格させない。

## 対象と読み込み制限

UTF-8のMarkdown・テキスト・JSON・YAMLや、TypeScript・Python・PHPなどのコードを扱う。対応拡張子は `src/shared/referenceFiles.ts` に集約する。

添付件数の従来の20件制限は廃止する。読み込みには、1ファイル256KiB、本文合計20MiB、1,000ファイル、2,000ディレクトリ、10,000走査エントリー、深度12の保護上限を引き続き適用する。上限や読込失敗は添付ごとの確認事項に表示する。これらはローカルの処理量の上限であり、全量をAIへ送信する許可ではない。

## 送信・更新・出所

- 添付は既定でローカル限定。外部AIで利用するには、利用設定から明示的に送信を許可する。
- 本文だけでなく、検索計画用のファイル名・タイトルにも送信許可を適用する。
- 確認済みローカル接続はLM Studio／Ollamaのloopbackかつクラウド名を含まないモデル。ローカルサーバー内部の外部転送まで検証するものではない。
- 外部接続時のローカル限定資料は送信から除外し、理由を記録する。ローカル限定情報を使用した過去の回答・派生情報は、引き続き送信先の制約を引き継ぐ。
- 検索計画でカタログを送った出所も会話に記録する。ローカル限定のメタデータを使った場合も、その回答を保守的にローカル限定として扱う。
- 信頼されていないワークスペースでは資料を読まない。保護パターン・ユーザーの除外設定を適用し、秘密情報や依存・生成物を除外する。
- シンボリックリンク・ジャンクション・範囲外参照を追跡せず、上限付きのファイルハンドル読み込みで検査する。
- 監視通知・手動再読み込み・送信時の定期再走査で索引を更新する。送信する本文は直前に境界とハッシュを再確認し、変更があれば送信を見送る。
- 出所ID・ハッシュ・行範囲・取得理由・送信有無・許可状態は送信計画と会話に記録する。過去の原文全体を再現する機能は持たない。
- 資料管理とAI要求は排他し、検索計画・読み込み・回答生成の中断を扱う。

## 検証

`npm test` で検索要求の検証、会話単位の保存と切り替え、メタデータを含む送信許可、Skills認識、コード読み込み、全文保持、走査境界、出所保存、利用量計測、既存の相談フローを検証する。Windowsの実ジャンクション検査にはリンク作成権限が必要。

F5では、直接入力・通常ファイル・フォルダー内Skillを添付し、別会話への切り替え、外部送信許可、送信予定と実際の参照箇所、検索準備中の中断を確認する。Activity Barが表示されない場合は、永続UI状態とView Locationsも確認する。
