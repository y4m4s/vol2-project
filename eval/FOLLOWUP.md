# ローカルLLM改善・追加検証（2026-09-15実測、09-16整理）

続く小〜中規模向けの検証と採用範囲は [SMALL_MEDIUM.md](SMALL_MEDIUM.md)。以下は前回ラウンド時点の記録。

## 結論と採用範囲

実装に残した最小修正は、**取得済みコード・追加仕様の保持**と、**ローカルモデル向けの数値変換の参照情報**。
`await`というキーワードだけのヒントを不合格にした評価基準も修正した。
**基本的なコード知識の誤答全般は未解決。総合品質の統計的優越は確認できていない。**
Set/Map、配列、非同期の広い仕様メモと、ヒント生成指示の全面的な変更は採用しない。

今回の採用はrubricの「回帰テストで確定した情報欠落の修正」を根拠とする限定的な修正である。
数値変換の参照は既知の誤答と追加例で確認した範囲の補強であり、モデル能力全般の改善や全用途でのChampion認定を意味しない。
`champion-*`は最終候補の実験名。holdoutも含め、全ケース合格という意味ではない。

## 何を修正したか

### ① 必要なコードが届かない

- RequestPlannerのlow時の先頭2,000文字カットを廃止。Collectorが取得・制限した断片を、モデル入力予算の範囲で保持する。
- 予算超過時は先頭だけでなく末尾も保持。質問に含まれる識別子が中間にあれば、その周辺も残す。省略箇所を明記し、全体の上限と参照境界を維持する。
- 追加コンテキストにも同じ保持処理を適用し、末尾の最新仕様を一律に削らない。
- 回帰テストは既知ケース以外の関数名・値で、中央と末尾の定義、追加仕様、入力上限を確認した。

修正範囲は**取得済み断片の送信前欠落**。Collectorの表示範囲外、除外ファイル、lowで除かれる関連ファイルを自動的に検索・送信する変更ではない。
Ollamaの実割当contextとNaviComの概算予算の不整合は今回変更しておらず、backend側の切り詰めは別の未解決項目。

### ② 基本知識の誤答

- JavaScript/TypeScriptでNumber/parseInt/parseFloat等に関係する短い標準仕様メモを、LM Studio/Ollamaのsystem promptに追加する。全文の文字数予算にも含める。
- 独自の同名定義・引数・代入が見える場合は補強を省く。保守的な文字列検査であり完全なスコープ解析ではない。
- 評価IDや期待回答で分岐せず、言語とAPI名で選択する。ユーザーコードの実行、新規依存、推論時の外部検索は行わない。
- 出典・適用限界は[言語仕様メモ](../docs/language-reference.md)。

**Setの順序や操作の追跡、配列境界、独自関数の契約を推測する誤りは残る。**
Setの順序説明が一度正しくなっても、削除・再追加の別例では最終要素を落としたため、Set用メモを採用しなかった。

### ③ 用途に合うヒント

- rubric v2では「awaitを使用してください」のような概念・API名・キーワードの提案は許容する。
- 「await fetch(...)」や三項演算子による具体的な置き換えコードは、ヒントだけの依頼では減点する。
- 旧v1のA/B packetと点数は履歴として保持。v2での比較には変更前のBaselineを取り直した。
- 生成指示を広げる案・日本語に置き換える案は副作用があり撤回。最終版の一般的な生成指示は元に戻し、評価基準の誤りを修正することに留めた。

## 具体的な結果

| ケース | 変更前 | 最終候補・確認結果 |
|---|---|---|
| 長い追加文脈の最新仕様 | 最新仕様が届かず、回答できない | 末尾の17秒が届き、17秒に正答 |
| 長いコード末尾のparsePort | 定義が届かずnull/undefinedを推測 | 定義を参照し、型number・空文字0に正答 |
| 数値変換の追加例・各2回 | 空白をNaN、不正文字列を0と誤答 | 0 / NaN / 19を2回とも正答 |
| 独自Number関数・各2回 | 広い補強では余計な空白や形式不正が発生 | 独自定義時に補強を省くとcustom: / stringに2回とも正答 |
| holdoutの長いコード末尾 | 今回は変更前回答未取得 | isReady(0)のfalse / booleanに正答 |
| Set / 配列境界 / DB原因推測 | 誤答あり | 未解決。改善済みと扱わない |

数値変換と独自定義の4回答は[追加確認](results/final-numeric-confirmation/assessment.json)。これは最終の一般指示を元に戻す前の補強部品の確認であり、最終版全体の4回試験と混同しない。

### 最終候補と新Baseline（tuning 13件、各1回）

- A/B: **2勝・10同等・1敗**。同等を0.5とする勝率53.8%、95% CI **42.3–65.4%**。
- Hard Check: **12/13 → 12/13**。既知の自動配置判定は未解決。
- 0–4点の軸別変化: correctness **+0.23**、groundedness **+0.15**、context utilization **+0.31**、hallucination **+0.23**、instruction following **+0.31**、pedagogy **+0.15**、actionability **+0.23**、conciseness **0.00**、Japanese **+0.15**。
- 所要時間中央値 **6.35 → 7.29秒（約15%増）**、p95 **21.16 → 25.55秒**、decode速度中央値 **13.10 → 13.29 tokens/sec**。
- 送信promptが変わったのは13件中3件。残り10件は同一で、ヒントの勝敗も同一promptからの出力変動だった。変更のないケースの差を修正の因果効果とはしない。

[全軸・各回答の評価](results/champion-comparison/report.md)。小標本、非固定sampling、実行時刻・cacheの差があるため、全般的な優越や速度の同等性は主張しない。

## Holdout：最終候補を固定後に1回

**形式6/6合格、内容上の主要要件を満たすのは3/6**。点数・理由は[holdout評価](results/champion-holdout/assessment.json)。

| ケース | 判定 |
|---|---|
| 課題文の同値時の出力 | 正答：同じ値を1回 |
| map→joinの説明 | 概ね正答。カンマ後の空白の説明は不足 |
| 長文末尾の関数 | 正答：false、boolean |
| 次の学習内容 | 既存mapの再実行のみ。「数组」の混入もある |
| await saveの永続性 | 未提示のsave契約を仮定し、保証を説明できない |
| address欠落のヒント | 原因は正しいが完成した三項演算子を提示 |

holdoutは数値変換メモが適用されない6件であり、数値補強の汎化評価を代替しない。
holdoutの回答を見た後のコード・prompt最適化は行わない。以後調整するなら新しいholdoutが必要。

## 判断履歴・再現性

各段階の比較・棄却理由は[rounds.md](rounds.md)。新規143観測、13生成run、10組のA/B比較を保存した。
初回を合わせると260観測（初回context診断18を含む）。失敗や試行を削除・成功回答に置換していない。
設定・source hash・prompt revision・実送信request・回答・速度は[実験一覧](results/experiments.json)に対応する。

今回の実モデル測定はLM Studio / Qwen3 8B / Q4_K_M / context 8,192。Ollamaは送信前の共通処理と回帰テストを確認したが、今回の最終版の実推論比較は未実施。
temperature等のsampling、Thinking、出力上限、backendのglobal設定、インストール済みモデル・ファイルは変更していない。
外部Judge/Copilot/OrcaRouter比較も未実施。同じCodexが設計と採点を担当し、完全な独立・盲検評価ではない。

検証: 本体テスト233件、評価基盤9件、lint成功。実エディタ操作によるCollectorの統合検証と、モデル知識全般の誤答解消は残る。
